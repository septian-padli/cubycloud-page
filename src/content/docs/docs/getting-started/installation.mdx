CubyCrate runs as one container with a Go backend and embedded web interface. This guide installs the published alpha image without cloning the source repository.

<Aside type="caution" title="Alpha release">
  CubyCrate is pre-release software. Do not rely on it as the only copy of important files. The `v0.0.1-alpha.2` image is published for `linux/amd64` and `linux/arm64`.
</Aside>

## Requirements

- Docker Engine with the `docker compose` plugin.
- A Linux `amd64` or `arm64` host.
- A writable persistent volume for `/app/data`.
- Host port `8383` available, or choose another host port in the Compose file.

## Install the published image

The application repository's Compose file defaults to `cubycrate:local`. Set both image variables before running Compose so it pulls the official published image instead.

<Steps>
1. **Create an installation directory**

   ```sh
   mkdir -p cubycrate && cd cubycrate
   ```

2. **Download the official Compose file**

   ```sh
   curl -fsSLO https://raw.githubusercontent.com/septian-padli/cubycrate/main/compose.yaml
   ```

3. **Select the published release**

   ```sh
   export CUBYCRATE_IMAGE=ghcr.io/septian-padli/cubycrate
   export CUBYCRATE_VERSION=v0.0.1-alpha.2
   ```

   These variables apply to the current shell. Keep them set for later Compose commands, or place them in a local `.env` file in this directory. Do not commit `.env` files.

4. **Pull and start CubyCrate**

   ```sh
   docker compose pull
   docker compose up -d
   ```

   The service publishes host port `8383` to container port `8383`. The named volume `cubycrate_data` persists `/app/data` across container replacements. Do not run `docker compose down -v` during normal updates.

5. **Check startup and open setup**

   ```sh
   docker compose ps
   docker compose logs --tail=100 cubycrate
   curl -i http://127.0.0.1:8383/health
   ```

   The Compose healthcheck probes `/health`. When the server is reachable, open `http://localhost:8383/setup` on the host or `http://<server-ip>:8383/setup` from a trusted network. Create the first administrator and configure a local or S3-compatible storage node.
</Steps>

For remote access, restrict direct HTTP access with a firewall. Configure HTTPS termination before exposing the service publicly. See [Configuration & Reverse Proxy](/docs/getting-started/configuration/).

## Release tags

Use the exact published tag `v0.0.1-alpha.2` for repeatable installs. The `alpha` tag is a moving alias and may point to a different alpha release later. The release workflow reserves `latest` for stable releases; do not use it for alpha installations.

## Updating this installation

Review the release notes and compatibility information before updating. Set `CUBYCRATE_VERSION` to the exact target tag, then run:

```sh
docker compose pull
docker compose up -d
docker compose ps
```

Keep the same named volume. A Compose file with a different volume name starts with separate data. Do not remove volumes as part of an update. Back up the application data and external storage first; see [Backup & Disaster Recovery](/docs/administrator-guide/backup-restore/).

## Development versus self-hosting

The instructions above use the published GHCR image. Building `cubycrate:local` requires cloning the application source and is a development workflow, not a prerequisite for self-hosting.

## Clean break from historical CubyCloud

Direct in-place upgrade from historical CubyCloud `v0.0.1-alpha.1` data is unsupported. A fresh CubyCrate installation uses a separate `cubycrate_data` volume and data layout. Keep historical CubyCloud volumes and backups intact if their data may be needed. Do not point a CubyCrate installation at an old volume.

The official Compose file sets `ENV=production` and `PORT=8383`. It persists application state in the `cubycrate_data` volume mounted at `/app/data`.

## Environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `8383` | HTTP listen port inside the container. The published host port is set by `CUBYCRATE_PORT` in Compose. |
| `DATA_DIR_PATH` | `/app/data` in the image | Root for SQLite, generated secrets, local storage, and temporary uploads. |
| `ENV` or `APP_ENV` | Unset | Set to `production` for production safety behavior. The official Compose file sets `ENV=production`. |
| `COOKIE_SECURE` | `false` | Set to `true` when clients access the app over HTTPS. Session cookies then require HTTPS. |
| `TRUST_PROXY` | `false` | Enables use of trusted reverse-proxy headers. Enable only when all access to the app passes through a trusted proxy. |
| `ALLOWED_ORIGINS` | Empty in production | Optional comma-separated CORS origins. Same-origin access does not require this setting; `*` is rejected in production. |
| `JWT_SECRET` | Generated and persisted | Optional session-signing secret. Keep its value stable if set explicitly. |
| `CUBYCRATE_MASTER_KEY` | Generated when needed | Optional encryption key for stored S3 credentials. Protect and back it up if set. |
| `CUBYCRATE_MASTER_KEY_FILE` | Unset | Path to externally supplied master key. Back up the referenced file separately. |
| `CUBYCRATE_STORAGE_CLEANUP_DRY_RUN` | `true` | Keeps orphan cleanup in audit-only mode unless explicitly changed. Review application guidance before enabling deletion. |
| `CUBYCRATE_PORT` | `8383` in Compose | Host port mapped to container port `8383`. |
| `CUBYCRATE_VERSION` | `local` in Compose | Image tag. Set it to a published exact release such as `v0.0.1-alpha.2`. |
| `CUBYCRATE_IMAGE` | `cubycrate` in Compose | Image name. Set it to `ghcr.io/septian-padli/cubycrate` for published images. |
| `CUBYCRATE_VOLUME_NAME` | `cubycrate_data` | Named volume used for `/app/data`. Changing it selects a separate data state. |

The image also accepts `TEMP_TUS_PATH` or `TUS_TEMP_PATH` to override temporary TUS upload storage. Keep temporary uploads on persistent storage if they must survive container replacement.

## Reverse proxy and HTTPS

Terminate TLS at a reverse proxy and restrict direct access to the container's HTTP port. Set `COOKIE_SECURE=true` when users access the site over HTTPS. Do not enable `TRUST_PROXY=true` while clients can also reach the published HTTP port directly; untrusted forwarded headers can affect proxy-aware request handling.

The application uses same-origin frontend requests for a standard single-domain proxy, so `ALLOWED_ORIGINS` is unnecessary for that setup. Add only the exact origins required by a separate frontend origin.

<Tabs>
  <TabItem label="Caddy">

    ```txt
    drive.example.com {
        reverse_proxy 127.0.0.1:8383 {
            flush_interval -1
        }
    }
    ```

    Caddy obtains and renews certificates for the configured domain. Confirm your firewall exposes HTTPS and limits direct access to port `8383`.
  </TabItem>
  <TabItem label="Nginx">

    ```nginx
    server {
        listen 443 ssl;
        server_name drive.example.com;

        ssl_certificate /etc/letsencrypt/live/drive.example.com/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/drive.example.com/privkey.pem;

        client_max_body_size 10G;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        location / {
            proxy_pass http://127.0.0.1:8383;
            proxy_http_version 1.1;
            proxy_read_timeout 600s;
            proxy_send_timeout 600s;
        }

        location /api/v1/events {
            proxy_pass http://127.0.0.1:8383;
            proxy_buffering off;
            proxy_cache off;
            proxy_read_timeout 24h;
        }
    }
    ```

    Configure an HTTP-to-HTTPS redirect separately if your deployment needs one.
  </TabItem>
</Tabs>

The example body limits are proxy settings, not application upload guarantees. Actual uploads remain subject to configured storage capacity and proxy limits.

## Health checks

- `GET /health` is used by the Docker healthcheck and checks whether the HTTP listener responds.
- `GET /api/health` checks SQLite connectivity and configured storage-node availability. It can return unavailable when a configured node is offline.

```sh
curl -i http://127.0.0.1:8383/health
curl -i http://127.0.0.1:8383/api/health
```

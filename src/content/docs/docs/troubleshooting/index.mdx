description: Diagnose common CubyCrate startup, storage, proxy, and health-check issues.

## Inspect service status and logs

Run these commands from the directory containing the instance's Compose file and environment:

```sh
docker compose ps
docker compose logs --tail=100 cubycrate
curl -i http://127.0.0.1:8383/health
curl -i http://127.0.0.1:8383/api/health
```

`/health` is the container liveness check. `/api/health` checks SQLite and configured storage-node availability.

## Container does not become healthy

Check `docker compose ps` and inspect the service logs. Confirm the published port is available and the image reference resolves. The official Compose file defaults to the local image `cubycrate:local`; set `CUBYCRATE_IMAGE` and `CUBYCRATE_VERSION` for the published image as shown in [Installation](/docs/getting-started/installation/).

## Setup keeps appearing

The setup wizard remains active until the initial administrator and storage configuration are saved. Check that `/app/data` is writable and persisted in the expected volume. Do not switch volume names while diagnosing; a new volume contains a separate installation state.

## Storage node or readiness probe is unavailable

`/api/health` can report unavailable when SQLite or a configured storage node cannot be reached. Check that local host paths are mounted into the container and writable. For S3-compatible nodes, check the configured endpoint, bucket access, network connectivity, and encryption key availability.

Configured capacity limits are separate from actual filesystem free space. Review both before increasing a quota or retrying an upload.

## Upload fails behind a proxy

Review the proxy request-body limit and timeouts. Ensure event-stream requests at `/api/v1/events` are not buffered. A proxy's body-size limit does not raise the application's storage capacity.

## SQLite reports a busy or locked database

Keep SQLite data on a local filesystem that supports its locking requirements. Do not place the live database directly on NFS or SMB mounts. Preserve the volume and inspect logs before attempting recovery.
